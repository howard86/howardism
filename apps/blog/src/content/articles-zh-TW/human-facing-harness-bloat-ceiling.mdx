## 資料來源

- [How I AI: Thariq Shihipar on Replacing Markdown with HTML for AI-Powered Development](https://www.chatprd.ai/how-i-ai/claude-code-anthropic-thariq-shihipar-on-replacing-markdown-with-html)

**問題：** 面向人類的 harness 會不斷膨脹，沒有上限嗎？還是也會碰上自身的膨脹上限——就像被它取代的 markdown 一樣，HTML 計畫變得繁複到難以閱讀？

*（這回答了 [HTML as the New Markdown](/articles/html-as-the-new-markdown) 中記錄的第一個未解問題。）*

## 簡答

**是——但 HTML 是提高並重塑上限，而非將它消除。** 膨脹上限是結構性的，因為面向人類的 harness 存在的目的，就是配合有限的人類注意力；沒有任何媒介能讓這項資源無限。HTML 提供了更多餘裕；豐裕經濟與 artifact 蔓延又會把餘裕消耗殆盡——而且模型越進步，消耗得越快。

## 論點

### 1. HTML 本身就是膨脹上限已被觸及的跡象——markdown 的上限

這個論點之所以成立，只因為千行的 markdown 計畫「會讓*人類*不堪負荷……我們開始看得眼花」([HTML as the New Markdown](/articles/html-as-the-new-markdown)；原始來源）。Thariq 坦承自己會「請 Claude 編輯計畫，而不是親自閱讀」，這正是*已經越過* markdown 可讀性上限的診斷。我們因此直接看到，供人理解的媒介可能膨脹到失去用途。眼前唯一的問題是 HTML 在結構上是否不受此限，而答案是否定的。

### 2. HTML 帶來的改變：提高上限並改變其形狀

- **提高上限。** HTML「把 token 花在易讀性上（模型稿、結構、色彩、互動），而不是原始文字」，讓每單位注意力承載更多可理解的訊息 ([HTML as the New Markdown](/articles/html-as-the-new-markdown))。這明確對應到模型的 smart zone在人類注意力上的版本：清空上下文能恢復模型的 smart zone，但二次方注意力仍然限制它；HTML 則提高人類的*有效* smart zone，卻不會消除上限 ([Context Window Smart Zone](/articles/context-window-smart-zone))。
- **重塑上限。** Markdown 是線性的——必須依序閱讀。HTML 可供瀏覽並逐步揭露資訊：略讀 → 深入查看 → 互動。限制因素從*總量*轉為*每個決策所需的注意力範圍*。[Disposable Micro-Apps](/articles/disposable-micro-apps) 是極端例子：把某個子決策收斂成聚焦的 UI，只呈現剛好需要的注意力內容，不多不少。這種分解式的逃生閥，正是單一大型 markdown 檔案所缺少的。

### 3. 但上限只是轉移，並未消失——從長度轉為蔓延

膨脹會在新軸線上重現：不再是「一份文件太長，讀不完」，而是「artifact 太多，難以掌握」。這是 [Disposable Micro-Apps](/articles/disposable-micro-apps) 已提出的未解問題（「一次性微型應用和工具蔓延之間的界線在哪裡？如果每次編輯都產生專屬 UI，工作流程會不會碎片化？」），再加上 HTML 在差異比對／版本管理上的弱點（只能靠複製回 markdown 部分補救），以及 [Living Design System](/articles/living-design-system) 提出的問題：「專案規模到多大時，維護 artifact 的成本會超過它帶來的一致性價值？」同一個上限，新的維度。

### 4. 讓上限具有結構性的恆定因素：人類注意力有限

限制因素是「人類注意力與判斷力，而非生成成本」([Compute Allocator](/articles/compute-allocator))。超出認知能力的監督會讓輕微錯誤增加 11%、重大錯誤增加 39% ([AI Brain Fry](/articles/ai-brain-fry))；人類超出負荷後也會出現退化曲線，與模型的 smart zone 相似 ([Context Window Smart Zone](/articles/context-window-smart-zone))。任何以促進人類理解為全部目的的 harness，*必然*受限於這項有限資源。某種媒介可以更有效地運用每單位注意力 token，卻無法讓注意力變成無限。

### 5. 關鍵的不對稱性——上限會隨時間變得*更有約束力*，而非更弱

*面向模型的* harness 會隨著能力內化而逐漸縮小，甚至趨近於零 ([Harness Shrinkage as Models Improve](/articles/harness-shrinkage-as-models-improve)、[The Bitter Lesson](/articles/the-bitter-lesson))。*面向人類的* harness 則做不到：模型變聰明時，人類的注意力預算不會跟著增加。更糟的是，豐裕經濟加上更快的產出，代表*更多* artifact 爭搶同一份固定預算。「產出更多、速度更快的代理程式會重新帶來數量壓力」([AI Brain Fry](/articles/ai-brain-fry))。所以模型越進步，面向人類的 harness 面臨的膨脹壓力就*越大*；正因為其他一切都變得便宜，注意力上限才成為主導性限制。這與面向模型的 harness 發展軌跡相反——能力越提升，兩者越分歧。

### 6. 如何讓它不觸頂——以及上限如何被突破

面向人類的 harness 有個面向模型的 harness 所沒有的膨脹偵測器：*你自己失去投入*。明確目標就是「做出一份你真的*想讀*的計畫」([HTML as the New Markdown](/articles/html-as-the-new-markdown))。面向模型的膨脹不易察覺——它會悄悄把模型推進愚笨區 ([Context Window Smart Zone](/articles/context-window-smart-zone))；面向人類的膨脹則在你開始看得眼花時立刻顯現。這是一種自我修正訊號。

它會透過 [Compute Allocator](/articles/compute-allocator)／[AI Brain Fry](/articles/ai-brain-fry) 所描述的失效模式被突破：豐裕讓生成變得免費，因此沒有任何*機制*阻止你產出超出注意力負荷的內容 → 注意力退化成橡皮圖章式審核 → 你在毫無察覺下越過上限。避免這種情況的紀律，是 Cat Wu 所說「每次啟動都閱讀完整的系統提示，並刪掉沒有存在價值的內容」([Harness Shrinkage as Models Improve](/articles/harness-shrinkage-as-models-improve))在人類端的對應做法：artifact 必須以你實際投入的程度證明自己值得存在，否則它就是膨脹。

## 結論

是，它會碰上上限。HTML 的作用是把上限*推遠*（提高資訊密度與易讀性），並讓它變得*不那麼陡峭*（可瀏覽、可分解，而非線性閱讀）；微型應用與複製回 markdown 則是逃生閥。但由於有限的人類注意力是不可增生的資源——而更好的模型會把*更多*生成內容灌進這份固定預算——面向人類的 harness 無法逃離膨脹。它只是把失效模式從「文件太長，讀不完」轉移成「artifact 太多／橡皮圖章式審核」；模型越進步，這個上限的約束力就越強，而非越弱。
